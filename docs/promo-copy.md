# Code is Law：AI 可以幫你寫訴狀，但誰來阻止它亂引判決？

前陣子，我莫名其妙被牽扯進一個案件。

老實說，案情很鳥，爭議金額也不高。衡量過律師費與時間成本後，我決定靠自己研究，再搭配 AI 準備答辯與法律文件。

最後，案件全勝。

但整個過程也讓我看清一件事：AI 很會寫，卻不代表它真的懂法律。

它可以在幾秒內產出一份看似專業的訴狀，條列完整、語氣肯定，甚至附上法條與判決字號；但只要真的逐條核對，就可能發現法條已經修正、判決根本不存在、裁判意旨被扭曲，甚至把當事人的主張誤寫成法院見解。

更麻煩的是，AI 的幻覺不會因為你多說一句「請仔細檢查」就自動消失。

## Code is Law，但規則必須被真正寫進流程

在軟體世界裡，**Code is Law**：程式碼決定系統可以做什麼、不能做什麼。

當 AI 開始參與法律工作，提示詞、工具與工作流程就是約束它的規則。如果規則只寫著「請小心回答」，模型仍然可以猜；如果規則要求它先查官方法源、只能引用已讀取的裁判、必須核對上下審關係，而且資料不足時應停止回答，幻覺才真正受到限制。

這也是 law-powers 的出發點：不是讓 AI 說得更有自信，而是把「查證後才能回答」寫成它必須遵守的流程。

## 第一套工具：mcp-taiwan-legal-db

[mcp-taiwan-legal-db](https://github.com/lawchat-oss/mcp-taiwan-legal-db) 是一套讓 AI 助理直接查詢台灣公開法律資料的 MCP Server。

它串接司法院裁判書系統、全國法規資料庫及憲法法庭資料，提供法規查詢、判決搜尋、裁判全文取得、釋字與憲法判決檢索，以及引用關係查詢等唯讀工具。

這解決的是法律研究中的「精確性」問題：法條是不是真的這樣規定？判決是不是真的存在？法院原文到底說了什麼？

## 第二套工具：tw-legal-rag

[tw-legal-rag](https://github.com/aa0101181514/tw-legal-rag) 則解決另一個更棘手的問題：一般人往往不知道該用什麼法律關鍵字搜尋。

它是一套開源的台灣裁判語意檢索 CLI，連接法律偵探建置、約有 2,200 萬筆裁判的 TLR 檢索服務。與傳統關鍵字搜尋不同，它可以直接用自然語言描述案情，尋找概念相近但用詞不同的判決，並附上裁判片段、引用連結及上下審關係。

law-powers 使用同一套 TLR 後端提供的 `dr-lawbot` Remote MCP 介面，讓 AI 可以直接進行語意判例檢索。不過，語意找到的結果只是研究線索，不等於法律結論；重要主張仍須閱讀判決全文並重新核對。

## law-powers：把工具變成一套法律攻防規則

有了資料庫，不代表 AI 就會正確使用它。

law-powers 會先整理當事人、事件時間、法律關係、爭點與證據缺口，再同步執行兩條判例檢索路徑：

- 以 `dr-lawbot` 從自然語言案情進行語意檢索，提升相關裁判的涵蓋率。
- 以 `taiwan-legal-db` 將口語轉換成台灣法律用語，進行關鍵字與結構化精確檢索。

兩邊找到的結果會依司法院裁判識別碼合併去重；判決尚未讀取理由書，就不能直接當成權威引用；判決若已被上級審廢棄，也會被排除或明確標示。

最重要的是，當資料不足時，技能要求 AI 停下來說「查無足以支持的依據」，而不是為了完成答案，臨時編出一條看似合理的法條或判決。

## 它能為法律攻防帶來什麼幫助？

在進攻面，技能可以協助整理請求權基礎、拆解構成要件、尋找相似案件、比對法院如何評價特定證據，並預先思考對方可能提出的抗辯。

在防守面，則可以逐項檢查對方主張是否欠缺法律要件、舉證是否完整、引用判決是否真的相關、裁判是否已遭廢棄，以及是否存在時效、程序或證據能力上的問題。

此外，技能包還能將案情、法條、判決、爭點與證據整理成法律關係圖，進行契約合規檢查，並把 AI 產生的文字校訂成符合台灣法律實務的繁體中文，同時保護日期、金額、訴訟聲明、抗辯與法源引用不被改變。

它不能取代律師，也不會保證勝訴。

但它可以把原本只會生成文字的 AI，變成一個會先整理案情、查找法源、核對引用、標示風險，而且知道證據不足時不能亂講的法律研究助手。

**Code is Law. 但當程式碼走進法律世界，Evidence must be the Gate。**

因為法律攻防最怕的，從來不是沒有漂亮的文字，而是寫了很多，卻沒有一句經得起查證。
