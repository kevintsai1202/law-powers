# Superset 各維度資料抽取方法論 (Superset Extraction Checklist)

本文件為 `legal-graph` 技能的子技能參考文件，提供逐維度的「抽取問題 / 來源技能 / 對應 superset 欄位」對照表，並詳細規範「法條關聯」連線 5 種 `rel` 的判斷準則。當主 `SKILL.md` 的步驟一／步驟二要求「參閱本文件」時，應依此表逐一檢查資料是否齊全。

## 各維度抽取對照表

| 維度 | 抽取問題 | 來源技能 | 對應 superset 欄位 |
| --- | --- | --- | --- |
| **fact**（人事時地物） | 案件的核心事實是什麼？涉案主體、發生時間、地點、事件經過為何？ | `legal-brainstorming` 步驟一（事實探索） | `group: "fact"` |
| **law**（適用法條） | 本案／本爭點適用哪些法條？條文原文為何？ | `legal-research`（構建檢索關鍵詞 → 調用檢索工具 → 引用驗證，需查證原文避免幻覺） | `group: "law"` |
| **judgment**（法院判決） | 判決字號為何？本方於該判決係勝訴、敗訴或部分勝訴（`status`）？有無判決全文連結（`url`）？ | `legal-research`（調用檢索工具取得字號與全文、引用驗證確保字號與內容一致） | `group: "judgment"`、`status`、`url` |
| **issue**（爭點/抗辯/主張） | 雙方的爭執焦點、可能的抗辯、具體的訴訟主張為何？ | `legal-brainstorming` 步驟三（爭點與抗辯分析） | `group: "issue"` |
| **party / plaintiff**（當事人及涉訟案件／契約） | 訴訟兩造分別是誰？各自涉訟於哪個 `judgment` 或 `fact`？契約情境：締約當事人是誰？契約地位（甲方／乙方／保證人）為何？ | `legal-brainstorming` 步驟一（事實探索中的主體提問，如「原告/被告、買方/賣方」）；契約情境自契約原文首部抽取 | `group: "party"` / `group: "plaintiff"`（契約當事人加 `role`）+ 「當事人」連線連到涉訟之 `judgment`／`fact` 或締約之 `contract` |
| **evidence**（關鍵證據） | 有哪些足以影響認定或判決結果的關鍵證據？各自對哪一方有利／不利（`favorable`）？證明力如何？ | `legal-brainstorming` 步驟四（證據需求清單與策略） | `group: "evidence"`、`favorable`（`strong`/`weak`）+ 「證據」連線連到所屬 `judgment`／`fact` |
| **法條關聯**（law↔law 體系關係） | 兩法條之間是構成要件銜接、備位、競合、特別法或時效銜接關係？ | 本文件下一節「法條關聯 rel 判斷準則」 | `label: "法條關聯"` + `rel`（`trigger`/`alt`/`absorb`/`lex`/`bridge`） |
| **family**（案件分群） | 本案是否與其他案件屬同一被告集團、同一系列產品或同一訴訟脈絡？ | 依當事人／案件家族歸類（如同一被告集團、同一系列產品） | 任一節點皆可加註 `family` 欄位 |
| **contract**（契約本體） | 系爭契約是什麼？契約性質（買賣／承攬／委任／租賃…）為何？ | 使用者提供之契約原文；性質定性可佐以 `legal-research` 查證對應法條 | `group: "contract"` + 「適用」連線連到定性法條 + 各契約當事人（`party`＋`role`）以「當事人」連線連入 |
| **clause**（契約條款） | 契約有哪些具法律意義的條款？各條款之風險評級為何？ | 契約原文逐條抽取；風險評級**必須**來自 `compliance-verification` 審查報告（🔴→`high`、🟡→`medium`、🟢→`low`），未經審查不標 `risk` | `group: "clause"`、`risk` + 「包含」連線（contract→clause） |
| **obligation**（契約義務） | 各條款課予誰什麼義務？誰是債務人、誰是債權人？義務屬主給付／從給付／附隨義務？ | 契約原文＋本文件下一節「義務 duty 分類準則」 | `group: "obligation"`、`duty` + 「課予」（clause→obligation）、「負擔」（債務人 party→obligation）、「得請求」（obligation→債權人 party）連線 |
| **對價／違約效果**（義務間與條款效果關係） | 哪兩個義務互為對價（雙務牽連）？違約金／解除權條款針對哪個義務？ | 契約原文（給付與對待給付之對應；違約條款之標的義務） | `label: "對價"`（obligation↔obligation）、`label: "違約效果"`（效果條款 clause→obligation） |

指示：Agent 產圖時應依上表**盡量抓齊所有維度（聯集精神）**，逐一檢查是否有可補充的 party/plaintiff/evidence/法條關聯/family 資料；契約情境並應抓齊 contract/clause/obligation 三層與對價、違約效果關係；資料不足時，才退回僅產出 `fact`/`law`/`judgment`/`issue` 四類節點的基本格式（見 `SKILL.md` 步驟一之向後相容聲明）。

## 法條關聯（rel）判斷準則

`label` 為 `"法條關聯"` 的連線，皆須加註 `rel` 欄位，並在 `title` 中以一句話說明兩法條間的具體關係。5 種 `rel` 值的判斷準則與範例如下：

1.  **`trigger`（構成要件 → 效果）**
    *   *判斷準則*：A 條規定的構成要件成立後，直接引發 B 條規定的法律效果（義務、責任、罪責）。兩條之間具有「若 A 則 B」的因果／推導關係。
    *   *例子*：著作權法 §87 各款「視為侵害」要件成立 → 依 §88 Ⅰ 負損害賠償責任；一般侵權行為構成要件（民法 §184）成立 → 數人共同侵害時依 §185 Ⅰ 負連帶責任。

2.  **`alt`（備位/擇一適用）**
    *   *判斷準則*：A 條與 B 條提供當事人可**擇一主張**或**備位主張**的請求權基礎或計算方式，非必然先後發生，而是訴訟策略上的選項。
    *   *例子*：損害賠償得依差額法（著作權法 §88 Ⅱ）或不易證明實際損害時備位改依法院酌定賠償額（§88 Ⅲ）；被害人得於侵權行為（民法 §184）與不當得利（§179）之間擇一或併行主張。

3.  **`absorb`（法條競合/吸收）**
    *   *判斷準則*：A 條與 B 條同時該當，但依實務見解或法條競合原則，其中一條的評價已涵蓋另一條，僅論以其一（通常是較重或較特別的規定吸收另一規定），不另論罪或不另計賠償。
    *   *例子*：意圖銷售而重製之罪（著作權法 §91 Ⅱ）與擅自公開傳輸罪（§92）同時成立時，實務見解認為重製罪吸收公開傳輸罪，不另論罪。

4.  **`lex`（特別法優於普通法）**
    *   *判斷準則*：A 條是特別法／特別規定，B 條是普通法／一般規定，兩者規範同一事項時，優先適用特別規定（`lex specialis derogat legi generali`）。
    *   *例子*：著作權法 §88 Ⅰ 為民法 §184 Ⅰ 一般侵權行為規定之特別規定，優先適用；著作權法 §89-1（2 年時效）為民法 §197 Ⅰ 之特別規定。

5.  **`bridge`（時效銜接）**
    *   *判斷準則*：A 條規定的請求權罹於時效消滅後，B 條提供另一項請求權基礎作為銜接（通常時效更長），使被害人仍能請求返還。用於連結「時效抗辯成功」與「改依他項請求權」兩個階段。
    *   *例子*：民法 §197 Ⅰ 侵權行為 2 年時效完成後，依 §197 Ⅱ 銜接至不當得利（§179）返還請求權（15 年時效）——即實務上「時效抗辯打贏、法院卻改依不當得利判賠」的關鍵路徑。

**判斷順序建議**：先確認兩法條是否同時該當同一事實（→ 檢查 `absorb`／`lex`）；再確認是否為請求權基礎的替代選項（→ `alt`）；再確認是否為時效完成後的銜接（→ `bridge`）；其餘構成要件與效果的直接推導關係，一律歸為 `trigger`。

## 義務（duty）分類準則

`group` 為 `"obligation"` 的節點，建議加註 `duty` 欄位標示民法給付義務分類；判斷準則與範例如下：

1.  **`main`（主給付義務）**
    *   *判斷準則*：決定契約類型、構成契約核心目的之給付義務；欠缺即無該契約。雙務契約中互為對價之兩個主給付義務，應以 **「對價」** 連線相連（此為同時履行抗辯《中華民國民法》第 264 條之基礎）。
    *   *例子*：買賣契約之「移轉財產權」與「支付價金」；承攬契約之「完成工作」與「給付報酬」。
2.  **`collateral`（從給付義務）**
    *   *判斷準則*：輔助主給付目的達成、使債權人之給付利益獲得最大滿足的義務；通常由條款明文約定，可獨立訴請履行。
    *   *例子*：出賣人交付使用說明書與保證書；承攬人之保固除錯義務。
3.  **`incidental`（附隨義務）**
    *   *判斷準則*：基於誠信原則（《中華民國民法》第 148 條第 2 項）產生之照顧、保密、保護、告知義務；通常不得獨立訴請履行，違反時依不完全給付請求損害賠償。
    *   *例子*：保密義務、僱用人對受僱人之安全保護義務、出賣人對標的物危險之告知。若附隨義務經契約明文約定（如保密條款），實務上亦得請求履行，仍得建立「得請求」連線。

**判斷順序建議**：先問「刪掉這個義務，契約還是不是這一類契約？」（否→`main`）；再問「是否為條款明文約定、輔助主給付之獨立給付？」（是→`collateral`）；其餘基於誠信原則之保護性義務歸為 `incidental`。
